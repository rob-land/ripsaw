# TheDiscDB submission pipeline

End-to-end flow for submitting a new disc (or correcting an existing
record) to https://github.com/TheDiscDb/data. The disc identification
side is covered in `identify.md`; this doc starts from
"identification done, user wants to submit."

## Output schema (TheDiscDB/data layout)

```
data/
├── movie/<Title (Year)>/                  # or series/<Title (Year)>/
│   ├── metadata.json                       # work-level
│   ├── cover.jpg                           # work-level poster (recommended)
│   ├── tmdb.json                           # optional raw TMDB dump
│   ├── imdb.json                           # optional raw IMDb dump (we don't write yet)
│   └── <release-slug>/                     # one folder per physical release
│       ├── release.json                    # release-level
│       ├── front.jpg                       # optional packaging photo
│       ├── disc01.json                     # one per disc in the release
│       ├── disc02.json
│       ├── disc01-summary.txt              # auto-generated by upstream (we don't write)
│       └── disc01.txt                      # auto-generated by upstream
```

`release.json` carries `ImageUrl`, `ReleaseDate`, `DateAdded`,
`Contributors`, `Groups`, `Locale`, `RegionCode`, `Upc`, `Asin`, plus
the slug/title/year/sort-title. `metadata.json` carries `Title`,
`FullTitle`, `SortTitle`, `Slug`, `Type` (Movie/Series), `Year`,
`ExternalIds {Tmdb, Imdb, Tvdb}`, `Plot`, `Tagline`, `Groups`.

The `disc01.json` shape lives in `identify::submission::render_disc_json`
and gets per-title details (display title, role, chapter titles,
duration, segment map, tracks) from the MakeMKV scan + TheDiscDB
identity (when matched) + per-title user edits from the detail page.

## Staging tree

Local staging root: `$XDG_DATA_HOME/ripsaw/discdb-submissions/data/`.
Mirrors the layout above exactly so the PR push step can `cp -r`
verbatim into the fork checkout. **Append-only across sessions** —
old staged submissions accumulate. The PR push scopes copy to the
specific submission's subpath; see
`memory/submit-pr-scope-staging.md` for the reasoning.

## Code map

- `identify::submission` — schema types (`MovieMetadata`,
  `ReleaseMetadata`, `DiscSubmission`, `SubmissionArtifacts`),
  renderers (`render_metadata_json`, `render_release_json`,
  `render_disc_json`), and stagers (`stage_full_submission`,
  `stage_full_submission_with`, `stage_submission`). The
  `_with` variant takes a `SubmissionArtifacts {cover_jpg,
  tmdb_json, front_jpg}` payload and writes the byte assets
  next to the JSON.
- `identify::tmdb::TmdbClient` — `fetch_movie` / `fetch_series` for
  the parsed details, `fetch_raw` for the JSON we drop into
  `tmdb.json`, `fetch_images` for the picker, `download_image` to
  fetch a chosen poster at any TMDB size (`"original"` for cover,
  `"w185"` for thumbs).
- `identify::submit_pr` — wraps `gh` + `git`:
  - `ensure_fork(user)` calls `gh repo view <user>/data`; if
    missing, `gh repo fork TheDiscDb/data --default-branch-only`.
  - `ensure_fork_checkout(user)` keeps a clone at
    `$XDG_CACHE_HOME/ripsaw/discdb-fork/`. Clone via `gh repo
    clone` so the remote is SSH-or-HTTPS per the user's gh auth
    protocol.
  - `sync_main_from_upstream(checkout)` adds an `upstream` remote
    pointing at TheDiscDb/data, fetches main, hard-resets the
    local main to it so each PR branches from the latest tip.
  - `copy_staged_data(staged_data_root, staged_subpath, checkout)`
    copies *only* the requested subpath (`series/<folder>` or
    `movie/<folder>`), never the whole staging tree. Skipping this
    scoping was the bug behind PR #355 needing a cleanup commit on
    2026-05-31.
  - `commit_and_push` and `open_pr` finish the workflow.
- `ui::cover_art_picker_dialog` — `AdwDialog` with a `FlowBox` of
  TMDB posters. `load_posters(Vec<TmdbImage>)` populates the grid
  and kicks off async w185 thumbnail downloads per child.
  `on_confirm(callback)` fires with the picked `TmdbImage` when the
  user clicks **Use selected**.
- `ui::title_list_page::submit_corrections` — assembles
  MovieMetadata/ReleaseMetadata/DiscSubmission from the disc-
  metadata rows, builds `SubmissionArtifacts` from
  `picked_cover_jpg` (set by the picker), calls
  `stage_full_submission_with`, then opens
  `https://github.com/TheDiscDb/data` for the user to PR.

## Manual end-to-end

1. **Identify disc**: drop in an ISO, click **Open Disc**, or drag
   an MKV. Page lands on `TitleListPage` populated by the
   identification pipeline.
2. **Fill in metadata**: TMDb ID → click the magnifier (auto-fills
   title/year/plot/tagline/IMDb). Click the image icon → poster
   picker → **Use selected**. UPC → magnifier (UPCitemDB,
   thin coverage — see `memory/upcitemdb-coverage.md`). Region
   pre-fills from VIDEO_TS.IFO on DVDs.
3. **Tick titles + per-title edits**: detail page edits land in
   the `title_edits` map; `display_title` overrides what shows in
   the filename + `disc01.json`'s title-level `Item.Title`.
4. **Submit corrections**: writes the staging tree, toasts the
   path, opens `https://github.com/TheDiscDb/data` in the
   browser. The user manually opens the PR from there (or uses
   the CLI driver below for full automation).

## Automated PR push (CLI)

Examples in `examples/dobie_gillis_submit_pr.rs` show the
end-to-end shape. The flow:

```rust
let staged_dir = stage_full_submission_with(
    &movie, &release, &disc, &scan, identity, &edits, &artifacts,
)?;
let data_root = staging_root().join("data");
let subpath  = PathBuf::from("series").join(&folder_name);
let result = push_pr(&PrPushRequest {
    staged_data_root: &data_root,
    staged_subpath:   &subpath,         // SCOPE THE COPY!
    slug:             &movie_slug,
    pr_title:         "Add ...",
    pr_body:          "...",
})?;
println!("PR: {}", result.pr_url);
```

The example honours `RIPSAW_DRY_RUN=1` to stop after staging so a
human can review before the PR fires.

## Known gaps

- **No `front.jpg` source**: the release-level packaging photo
  isn't sourced from anywhere yet. `SubmissionArtifacts.front_jpg`
  is wired through but no UI surface fills it. Candidates:
  UPCitemDB images (when present), Amazon PA-API (paid),
  user-supplied file via a chooser.
- **No `imdb.json`**: TheDiscDB existing records include a raw
  IMDb data dump alongside `tmdb.json`. IMDb has no free API, so
  this is realistically a "user pastes the dump" or "fetch via
  TMDB's `external_ids` + leave it sparse" path.
- **No `disc01-summary.txt` / `disc01.txt`**: TheDiscDB's build
  pipeline generates these from `disc01.json`. We don't ship them
  in submissions; maintainers regenerate post-merge.
- **PR push is one-shot**: there's no "open a fresh PR for the
  same submission" or "amend in place" support. If the PR needs
  changes after open, the user pushes to the same branch
  manually (the cache fork checkout is left in place).
